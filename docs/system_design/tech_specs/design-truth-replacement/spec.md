# Spec: замена системы контроля архитектурной истины

Status: draft v2 · 2026-07-31
Branch: `feature/design-truth-replacement`
Origin: пункты 1–9 реестра открытой работы ([../../../backlog/backlog.md](../../../backlog/backlog.md))
закрываются этой заменой; пункт 10 (dbt) к ней не относится.

## 0. Что и зачем

`docs/system_design/design_truth/` — 4830 строк из 5389 отслеживаемого содержимого
репозитория без лок-файла, то есть **90 %**. Продуктового кода — ноль строк.
Система зелёная (141 тест, 16,6 с, покрытие 91,94 %; 27 мутаций убиты за 5 мин 58 с),
и при этом не выполняет того, ради чего строилась. Замеры — в §«Обоснование».

Замена ставит на её место три артефакта с разными писателями и три инструмента,
у каждого из которых живой вход появляется с первого модуля кода.

**Граница задачи:** меняется только система контроля истины. Продуктовая
постановка (`../../architectural_vision.md`) не пересматривается; из неё правится
§6 — ссылка на удаляемую карту — и §5/§9, куда переезжают поведенческие решения
процессов.

## 1. Целевая раскладка

| Артефакт | Писатель | На какой вопрос отвечает | Чем проверяется |
|---|---|---|---|
| `docs/system_design/domain.yaml` | человек | что такое понятие и чем оно не является | `tools/truth_check.py` |
| `docs/system_design/domain_glossary.md` | генератор | то же, для чтения | сверка свежести там же |
| `[tool.importlinter]` в `pyproject.toml` | человек | кто от кого вправе зависеть | `lint-imports` |
| `docs/backlog/backlog.md` | человек | сквозная незакрытая работа | глазами |

Подстановочность реализаций порта проверяет `mypy`, уже стоящий в гейте.

**Слой модуля — это его каталог, а не строка в карте:**

```
src/pretraga/
├── domain/     # сущности, значения, ПОРТЫ (typing.Protocol). Импортов наружу — ноль
├── usecases/   # сценарии: триаж, дедупликация, обогащение, слой запросов, синтез
├── adapters/   # реализации портов: git-реестр, встраиваемое хранилище, сеть, замок писателя
└── entrypoints/  # ведущая сторона: cli.py сейчас, mcp.py когда придёт (видение §8)
```

Соответствие «слой = каталог» не требует рукописного отображения и не может
разъехаться с кодом: контракт `layers` перечисляет пакеты, а пакет — это каталог.

**Две стороны адаптеров разведены по кольцам.** `adapters/` держит только
**ведомую** сторону — то, что сценарии вызывают ЧЕРЕЗ порт (реестр, хранилище,
сеть, замок). Ведущая сторона — то, что само вызывает сценарии, — живёт в
`entrypoints/`. Без этого первый же MCP-модуль ляжет в `adapters/` по созвучию
имени.

`entrypoints` вправе импортировать `adapters`: это корень композиции,
единственное место, знающее конкретные реализации и передающее их сценариям.

## 2. Источник истины: `domain.yaml`

Пять полей у понятия вместо нынешних двенадцати. Ни `group`, ни `layer`, ни
`implements`, ни `attributes`, ни `relations`.

```yaml
# Домен PretRAGa — ЕДИНСТВЕННЫЙ рукописный источник модели.
# Машина сюда не пишет: расхождение разрешает человек, а не перезапись.
preamble: |
  «Источник» в модели не используется — слово зарезервировано за живой речью;
  поток документов из настроенного места добычи называется каналом добычи.
  «Кандидат» — стадия жизненного цикла Документа, не понятие.
  «Корпус» — предикат состояния (все активные документы реестра), не хранимое.

triggers:
  ingest_spec:      "спецификация ингеста"
  conversion_spec:  "спецификация конвертации"
  enrichment_spec:  "спецификация обогащения"
  synthesis_spec:   "спецификация мастерской синтеза"
  acquisition_spec: "спецификация добычи"

chains:
  provenance:
    ru: "цепочка улики: от деливерабла до сырья, оба звена версионированы"
    hops: [Deliverable, Claim, ProvenanceAnchor, CanonicalText, ConversionRecord, RawPayload]

entities:
  - id: Document
    ru: "Документ"
    kind: entity                 # entity | value | derived | port
    definition: |
      Единица корпуса, уровень «работы». Идентичность чеканится на стадии
      кандидата и никогда не пересчитывается; сопоставимость — отдельный
      механизм на схематизированных координатах происхождения.
    open:
      - {question: "состав минимума приёмки", trigger: ingest_spec}
```

**Четыре породы**, и порода — одно слово в определении, а не шесть колонок
обязательств:

| Порода | Смысл |
|---|---|
| `entity` | жизненный цикл, чеканный непрозрачный идентификатор |
| `value` | неизменяемое, контент-адресуемое |
| `derived` | восстановимо из источника, назад не пишет |
| `port` | интерфейс, объявленный доменом, реализуемый снаружи |

**Объявленный, но ещё не использованный триггер законен.** Правило «значение
словаря и его первый носитель одним коммитом» было измеренной помехой (записано
в `docs/backlog/ports_and_layers_brief.md` как ограничение реализации), а не инвариантом.

Состав: ~20 понятий, порядка 250 строк — против 891 строки нынешнего YAML и
1315 строк трёх сгенерированных представлений.

## 3. Контракт колец

В `pyproject.toml` — формат проверен исполнением, `import-linter` читает конфиг
оттуда и не требует `setup.cfg` (см. «Обоснование», §О5).

```toml
[tool.importlinter]
root_packages = ["pretraga"]
include_external_packages = true

[[tool.importlinter.contracts]]
name = "Кольца: зависимости смотрят внутрь"
type = "layers"
layers = ["pretraga.entrypoints", "pretraga.adapters", "pretraga.usecases", "pretraga.domain"]

[[tool.importlinter.contracts]]
name = "Одна дверь наружу: сеть только в адаптере"
type = "forbidden"
source_modules = ["pretraga.domain", "pretraga.usecases"]
forbidden_modules = ["urllib", "httpx"]
```

Второй контракт делает проверяемым правило `CLAUDE.md` §9 («вся броня повторов —
в ОДНОМ общем клиенте»), которое сегодня существует только прозой. По тому же
образцу добавляется дверь к хранилищу, когда движок будет выбран: до выбора
запрещать нечего, и записывать имя движка заранее значило бы зафиксировать
решение, которое видение оставляет за этапом реализации.

Имя ещё не установленного пакета в `forbidden_modules` законно и контракт не
глушит: проверено — со списком `["urllib", "httpx"]` при отсутствующем `httpx`
нарушение по `urllib` по-прежнему ловится.

**Третий контракт заводится, когда входов станет два**, и не раньше — контракт
на один модуль ничего не утверждает. Проверено на стенде: ловит `mcp → cli` с
файлом и строкой, exit 1.

```toml
[[tool.importlinter.contracts]]
name = "Входы не знают друг о друге"
type = "independence"
modules = ["pretraga.entrypoints.cli", "pretraga.entrypoints.mcp"]
```

## 4. `tools/truth_check.py`

Порядка 150 строк. Прототип на 133 строки прогнан на стенде; недостающее —
разбор `chains` и `triggers`.

**Блокирует** — то, что чинится без дизайн-решения:

1. YAML не грузится; **дубль ключа возбуждает исключение** вместо тихой победы
   последнего значения (механизм переносится из `entity_map_build.py` дословно).
2. У понятия нет `id`/`ru`/`kind`/`definition`; `kind` вне четырёх; дубль `id`;
   `trigger` вне блока `triggers`; звено `chains` — необъявленное понятие.
3. **Публичный тип в `src/pretraga/domain/`, которого нет в `domain.yaml`.**
   Понятие вошло в систему мимо решения; чинится одной правкой — переименовать
   или внести.
4. `domain_glossary.md` отсутствует, протух или правлен руками.

**Считает и называет** — то, что закрывается решением человека:

5. `i N из M понятий пока без кода: …`
6. `i N открытых вопросов`, разбивка по триггерам.
7. `i порт X пока без реализации` — Protocol в `domain/`, который никто вне
   `domain/` не наследует.

**Инертно и честно об этом говорит**, пока нет моделей:

8. Несущая цепочка по аннотациям типов: у каждого звена есть поле, ссылающееся
   на следующее. Пока в `src/pretraga/domain/` нет ни одного звена — печатается
   `i цепочка provenance: 0 из 6 звеньев в коде, проверка отложена`.

**Стена развёрнута.** Сейчас блокирует «сущность без кода» — состояние,
нормальное для проектирования и не чинимое иначе как заякорив все 36 разом.
Будет блокировать «код без сущности» — состояние ненормальное и чинимое одной
строкой.

Чекер не рисует, не хранит вокабуляры сверх `triggers`, не считает обязательства
пород и не планирует удаление.

**Почему `tools/`, а не рядом с картой.** Прежний довод («порознь инструмент и
документ бессмысленны») перестаёт действовать: чекер читает `src/`, а не только
свою папку, — это инструмент репозитория, и место конфигурации и инструментов
репозитория — корень (`CLAUDE.md` §2).

**Требование герметичности к сигнатурам.** Пути к карте, представлению и слою
домена — аргументы функций со значениями по умолчанию, указывающими на продакшн,
а не константы модуля. Тест, вызывающий точку входа, обязан передать временные
пути явно (`CLAUDE.md` §10); при константах модуля случайный вызов `main()`
перезаписал бы настоящее представление.

## 5. Гейт, CI, хук

Локальный гейт — пять шагов, ни одного списка путей (свойство сохраняется):

```
ruff check \
  && git ls-files --cached --others --exclude-standard '*.py' | xargs -r python -m mypy \
  && python -m pytest -m "not heavy" --cov --cov-report=term-missing \
  && lint-imports \
  && python tools/truth_check.py
```

CI (`.github/workflows/ci.yml`) — те же пять шагов, каждый с `if: '!cancelled()'`;
шаг `Entity map conformance` заменяется на `Domain truth` (коммит 3), шаг
`Import contracts` добавляется вместе с первыми пакетами (коммит 6). Правило «при расхождении команда сверяется с CI, а не
наоборот» остаётся.

`[tool.coverage.run] source` меняется с `["src", "docs/system_design/design_truth"]`
на `["src", "tools"]`. **Порог `fail_under` перемеряется** после коммита 3 ровно
той командой, что стоит в CI, и ставится на два пункта ниже измеренного: перенос
порога с прежнего кода был бы числом, снятым с другого объекта.

Хук `.claude/settings.json` (вне git) переводится на `truth_check.py --hook`.
Понижение при правке самого инструмента сохраняется: правка генератора
переопределяет, что такое «свежее представление», и блок, невыполнимый посреди
рефакторинга, учит игнорировать блоки.

## 7. Зависимости

12 из 14 прод-зависимостей `pyproject.toml` не импортирует никто. Живые две —
`PyYAML` (5 мест) и `networkx` (**одно** место: построить граф ради
`degree(node) == 0`). Удаляются 12 неиспользуемых и `networkx`; `PyYAML`
остаётся — его читает чекер. Проверка изолированности понятия исчезает вместе
с графом связей.

Дев-группа: `import-linter` и `grimp` остаются и впервые получают потребителя;
`erdantic` и `pydeps` остаются как замена рисованию схем из кода (`dot` в системе
есть). `types-networkx` уходит вместе с `networkx`.

Возврат зависимости — решение спецификации того блока, который её импортирует.

## Обоснование решений и отклонённые альтернативы

Все цифры сняты исполнением на копии репозитория, не взяты из документов.

**О1. Почему не точечная починка по бэклогу.** Пункты 1, 2, 4, 7 закрывают стену
и направление зависимостей, оставляя 39 сущностей семи природ, 4830 строк и
самореферентность. Отклонено: чинит симптомы, повышая стоимость сопровождения.

**О2. Почему не новый репозиторий.** 90 % отслеживаемого содержимого — это
удаляемая система; остальные 559 строк (CI, pyproject, игноры, `.env.example`,
видение, бэклог) переживают замену на месте. Новый репозиторий стоит потери
21 коммита истории, пяти веток dependabot, настроенного remote и `.claude/`
(он в gitignore и не переедет), а даёт измеримо ноль: чистый `pyproject` — это
удаление тринадцати строк. Отклонено. **Условие пересмотра:** пересмотр
продуктовой постановки, а не только системы истины.

**О3. Почему инфляция понятия сущности — структурная, а не количественная.**
Два замера штатным `--removal-impact`:
- удаление всех 12 процессов оставляет без носителей типы связей `reads` и
  `uses` — это **все** типы класса `dependency`. Единственная архитектурная
  проверка системы держится исключительно на породе, которая объектом не
  является;
- удаление трёх хранилищ роняет 15 связей, изолирует `Corpus` и `WriterLock` и
  поднимает открытые обязательства с 20 до 29, потому что `data` требует
  `placement`, `placement` требует цель, а `store` требует `hosts` —
  самооправдывающийся треугольник.

Отсюда решение: разделить модель данных и модель модулей, а не сокращать список.

**О4. Почему проверка направления перестаёт жить в карте.** `_validate_layering`
фильтрует связи по классу `dependency` — 15 из 85. Классы `placement` (11) и
`governance` (9) исключены сознательно. При раскладке тех же 39 сущностей по
кольцам Clean Architecture наружу смотрят 4 связи из 15 при счёте только
`dependency`, 13 из 26 с добавлением `placement` и 20 из 76 по всем классам,
кроме governance; 11 из этих 20 — `stored_in` от доменной сущности к хранилищу.
Система показывает ноль, потому что не смотрит туда, где нарушения живут.

Отсюда же: `placement` — категориальная ошибка в терминах Clean Architecture.
`stored_in` есть факт размещения, а не зависимость; обязательство
`placement: required` заставляет домен знать, где он лежит.

**О5. Почему `import-linter`, а не генерация контракта из карты.** Контракт на
два десятка строк, собранный на стенде против игрушечного CA-дерева, поймал три класса
нарушения — домен → инфраструктура, сценарий → адаптер напрямую, сценарий →
сетевая библиотека — назвав файл и строку, exit 1; на чистой раскладке
`Contracts: 2 kept, 0 broken`, exit 0. Живой вход с первого модуля,
инкрементально, без рукописного отображения «модуль → слой».

Тот же контракт проверен в формате `pyproject.toml` (`[tool.importlinter]` плюс
`[[tool.importlinter.contracts]]`): отдельный `setup.cfg` не нужен, правило
`CLAUDE.md` §2 «конфигурация инструментов лежит в корне» соблюдено.

Генерация контракта из блока `layers` (пункт 7 бэклога) отклонена: нынешний
порядок ставит инфраструктуру самым стабильным слоем, и сгенерированный из него
контракт **запретил** бы переход к Clean Architecture, а не обеспечил его.

**О6. Почему порты не получают своей породы в проверке.** `mypy` на адаптере с
несовпадающей относительно `Protocol` сигнатурой выдаёт
`This violates the Liskov substitution principle` с именами типов. Инструмент
уже стоит и уже в гейте. Порода `port` в `domain.yaml` нужна только для
человеческого чтения и для счётчика «порт без реализации».

**О7. Почему якорь выводится, а не пишется.** `CLAUDE.md` §4 запрещает
рукописные бухгалтерские поля. Нынешний `implements` — список префиксов пути:
проверено, что `implements: [src/]` у одной сущности гасит проверку сирот
целиком, то есть гранулярность якоря не контролируется ничем. Имя понятия и так
объявлено именем в коде — сверка по символу строже и не требует поля.

**О8. Почему «понятие без кода» перестаёт блокировать.** Проверено на стенде:
`mkdir src` на пустом каталоге даёт exit 1; заякорить одну сущность не помогает
(36 → 35, по-прежнему ERROR); хук возвращает `"decision": "block"` на первую же
запись в `src/`. Чтобы написать первый модуль, надо заранее заякорить все 36
сущностей. Блокировать следует обратное направление.

**О9. Почему теряется `--removal-impact`.** Инструмент считает цену сужения по
графу связей. Графа связей в `domain.yaml` нет — цена удаления понятия сводится
к grep по имени. Переносить нечего.

**О10. Почему представление одно, а не три.** Рендеринг занимает около 481 строки
из 905 в `entity_map_build.py` и производит 1315 строк, сверяемых побайтово.
Полный граф из 39 узлов и 85 рёбер в одном mermaid-блоке нечитаем по построению.
Схемы после появления моделей рисуют `erdantic` (ER из моделей) и `pydeps`
(граф импортов) — оба из реального кода.

**О11. Глубина реза.** Принята максимальная: механизм сохраняется только при
доказанном живом входе либо при цене в единицы строк. При иной постановке —
если бы главной ценностью системы были признаны терминологическая дисциплина
или реестр открытого — сохранялось бы больше: четыре статуса атрибутов вместо
одного поля `open`, отдельный реестр незакрытого, планировщик удаления.

**О12. Почему клиентов библиотеки трое, а колец четыре.** Видение §8 называет
три клиента, и кольцом не становится ни один из них: сессии Claude Code — не
код, а действующее лицо, вызывающее консольную команду; движок-оркестратор — не-цель
MVP (§3), и когда придёт, он либо внешняя программа, либо сама аналитическая
логика, то есть `usecases/`; обёртка MCP — код, но по природе ведущий адаптер,
равноудалённый от домена ровно как CLI.

Кольцо есть расстояние до домена, а не протокол. Поэтому CLI и MCP — один
каталог `entrypoints/` с двумя модулями, а не два кольца: контракт `layers`
задаёт полный порядок, и запись их отдельными слоями утверждала бы, что один
вправе импортировать другого. Для сиблингов существует отдельный тип контракта
(`independence`, §3), и он заводится вместе со вторым входом.

Имя `cli` для этого кольца отклонено: оно верно ровно до появления MCP, после
чего лжёт, а переименование задевает каждый импорт и строку контракта.

**О13. Названные остатки — то, что замена не чинит.**

- Правило «у каждого артефакта один писатель» (`CLAUDE.md` §4) остаётся прозой:
  пункт 4 бэклога предлагал поле `writer` у сущностей, но писатель есть у
  артефакта, а не у понятия домена, и после ухода хранилищ и файлов данных из
  модели носителя для такой проверки нет. Удвоение правила идентичности эта
  спека снимает; проверяемость «одного писателя» — нет.
- Направление зависимостей не проверяется до появления первого модуля. Раньше
  оно «проверялось» на рукописном графе, то есть было гипотезой; теперь его
  просто нет, и это честнее, но не сильнее.
- Схемы не рисуются, пока нет моделей.

## Тестовое покрытие

Глубина названа качественно там, где числовой порог был бы снят с другого
объекта; порог покрытия перемеряется в коммите 3 (§5).

**Коммит 1 — `domain.yaml`, генератор и `truth_check.py` вместе с тестами.**
Инструмент и его тесты одним коммитом: `[tool.coverage.run] source` получает
`tools` в этом же коммите, а порог 90 % действует сразу — инструмент без тестов
уронил бы гейт, и это правильно.

- регрессия: `domain.yaml` валиден; сгенерированный глоссарий совпадает со свежим рендером;
- негатив на каждую блокирующую проверку §4.1–§4.4 отдельным тестом: непарсящийся
  YAML, дубль ключа (проверить заодно, что стоковый `yaml.safe_load` то же самое
  принимает молча), отсутствие каждого из четырёх обязательных полей, `kind` вне
  словаря, дубль `id`, неизвестный триггер, звено цепочки вне списка понятий,
  отсутствующее представление, протухшее представление, правленое руками;
- трассировка — против **временного пакета во `tmp_path`**, не против `src/`:
  публичный тип в слое домена, которого нет в карте, даёт ошибку и exit 1;
  понятие без кода даёт информационную строку и exit 0 (ключевая проверка
  развёрнутой стены); порт без реализации попадает в счётчик, но не в ошибки;
  цепочка без звеньев в коде сообщает об отложенности, а не о зелени;
- интеграционные, подпроцессом против копии каталога: прогон без аргументов,
  `--build`, `--hook`; хук обязан выдать JSON даже на нечитаемой карте;
- герметичность: `conftest.py` переносится **дословно** — снимок каталога до и
  после каждого теста, падение с именем изменившегося файла.

**Коммит 2 — мутационный стенд:** около 10 мутаций вместо нынешних 25 (проверок
стало меньше). Нынешние 27 идут 5 мин 58 с; десять уложатся примерно в 2,5 минуты.
Остаётся под маркером `heavy`, вне гейта по умолчанию. Сохраняются структурные
тесты стенда: якорь мутации совпадает ровно один раз (дёшево, поэтому в обычном
гейте) и ни один тест, порождающий вложенный прогон, не остался без маркера.

**Коммит 6 — контракт колец:** мутация, которой не было в старой системе:
подсадить импорт `usecases → adapters` в копию дерева и потребовать, чтобы
`lint-imports` вернул ненулевой код. Без неё контракт — такой же механизм без
доказательства работоспособности, как всё, что эта спека разбирает.
