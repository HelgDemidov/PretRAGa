# Сквозной словарь сущностей PretRAGa

СГЕНЕРИРОВАНО из `entity_map.yaml` скриптом `entity_map_build.py` — руками
не править. Единственный канал изменения сущностей, терминов, определений
и конвенций — `entity_map.yaml` (конвенции — его блок `conventions`).
Писатель этого файла — генератор; ручная правка ловится проверкой свежести.

## Терминологические конвенции

- Слово **«источник»** в модели данных не используется. В живой речи оно означает
  отдельную публикацию/документ — и потому зарезервировано за человеческим языком.
  Поток документов из настроенного места добычи называется **каналом добычи**.
- **«Кандидат»** — не сущность, а стадия жизненного цикла Документа (до приёмки в корпус).
- Код — только английский; в скобках у каждой сущности — её имя в коде.

## Конвенции идентичности

- Сущность с жизненным циклом получает **чеканный идентификатор** (непрозрачный,
  время-упорядоченный, класса UUIDv7) один раз, при первом появлении; он никогда не
  пересчитывается и не участвует в сравнении «то же самое или нет».
- Неизменяемое значение **контент-адресуется** — ключ равен хэшу содержимого.
- Сравнение и сопоставление — отдельный механизм на отдельных атрибутах
  (естественных координатах); ненадёжное значение не даёт ключа вовсе.
- Ключ, разрешающийся в несколько сущностей, отзывается; сущности не сливаются автоматически.

## Конвенции писательства

- У каждого артефакта **один писатель**; писатель по умолчанию — машина.
- Поле, которое может заполнить только человек, обязано оправдать себя на
  кардинальности десятков (каналы, словари, таблицы правил), а не тысяч (документы).
  У документа обязательных ручных полей — ноль.
- Человеческие решения входят в систему **командами инструмента**, а не правкой
  машинных файлов; единственная руками правимая поверхность — файлы поправок.
- Машина никогда не пишет в человеческие файлы.

## Добыча

### Коннектор (Connector)
*Порода: запись расширения (`extension`) — запись таблицы расширений; новая разновидность — запись, а не правка ядра. Слой: Добыча (`acquisition`).*

Код добычи для класса мест публикации; запись в таблице расширений. Идентичность:
имя типа + версия записи; собственного id нет. Новый коннектор — новая запись,
а не правка ядра. Ручная загрузка файлов и списки URL — вырожденные коннекторы
с тем же контрактом.

### Канал добычи (AcquisitionChannel)
*Порода: данные (`data`) — хранимое с собственной схемой; получит pydantic-модель и дифф с ней. Слой: Добыча (`acquisition`).*

Настроенный экземпляр коннектора, дающий поток документов («EUR-Lex с запросом
по ИИ» и «EUR-Lex с запросом по кибербезопасности» — два разных канала). Операционная
конфигурация, не доменная сущность: расписание и периодичность опроса, заявленное
покрытие, объявления гомогенности атрибутов, гигиена входа (Gate 0 — детерминированные
фильтры без суждения о релевантности). Маленький иммутабельный id — только чтобы
провенанс документов переживал переименования. Машинное состояние забора (курсоры,
ошибки, карантин) — отдельный артефакт. Каналы выводятся (retire), не удаляются.

### Акт добычи (AcquisitionAct)
*Порода: данные (`data`) — хранимое с собственной схемой; получит pydantic-модель и дифф с ней. Слой: Добыча (`acquisition`).*

Машинная запись журнала: какой канал, когда, что принёс. Писатель — машина.

### Сырой payload (RawPayload)
*Порода: данные (`data`) — хранимое с собственной схемой; получит pydantic-модель и дифф с ней. Слой: Добыча (`acquisition`).*

Скачанное тело документа как получено: неизменяемое значение, контент-адресованный
файл. Хранится и для отвергнутых кандидатов. Первичный артефакт, а не производный:
веб гниёт, сырьё лишь частично восстановимо повторным скачиванием — поэтому оно
не живёт внутри стираемого файла базы.

### Подсказка добычи (AcquisitionHint)
*Порода: производное (`derived`) — восстановимо из источника, назад не пишет; инвалидируется версией. Слой: Добыча (`acquisition`).*

Производный сигнал пере-наполнения корпуса: висячие типизированные ссылки —
документы, которые корпус цитирует, но не содержит. Машинно-генерируемая
очередь кандидатов на добычу.

## Документ и содержимое

### Документ (Document)
*Порода: данные (`data`) — хранимое с собственной схемой; получит pydantic-модель и дифф с ней. Слой: Реестр корпуса (`registry`).*

Единица корпуса; сущность с историей (уровень «работы» — Work). Идентичность —
чеканная, выдаётся на стадии кандидата. Сопоставимость — через схематизированные
координаты происхождения: пары «схема + значение» (ELI, CELEX, номер в реестре,
канонический URL). Жизненный цикл — закрытое множество: **кандидат → активен →
выведен**; приёмка автоматическая (минимум приёмки), вывод — решение человека,
внесённое командой. Классификационные атрибуты (издатель, тип, юрисдикция, уровень,
обязательность, язык, тематики) — значения контролируемых словарей, заполняются
машинно: детерминированно из payload коннектора либо извлечением с меткой inferred
и уверенностью; неуверенное — в очередь исключений. Класс авторитетности не
хранится — вычисляется таблицей правил.

### Версия содержимого (ContentVersion)
*Порода: данные (`data`) — хранимое с собственной схемой; получит pydantic-модель и дифф с ней. Слой: Конвертация (`conversion`).*

Неизменяемое значение с **двухосным ключом (язык, редакция)**: перевод — не новая
редакция, новая редакция — не перевод. Повторный забор с изменившимся содержимым
порождает новую редакцию того же Документа. Payload версии контент-адресован.

### Канонический текст (CanonicalText)
*Порода: данные (`data`) — хранимое с собственной схемой; получит pydantic-модель и дифф с ней. Слой: Конвертация (`conversion`).*

Markdown-представление версии содержимого — **единственный несущий формат** корпуса
(целостность якорного пространства). Внутри законны структурные острова: таблицы
и mermaid-блоки; они якорятся как обычный текст, а их производство проверяется
реальным рендером. Контент-адресован; связан с сырьём версионированной записью
конвертации — это второе звено провенанса (транскрипции OCR и диаграмм наследуют
свою оговорку через него).

### Запись конвертации (ConversionRecord)
*Порода: данные (`data`) — хранимое с собственной схемой; получит pydantic-модель и дифф с ней. Слой: Конвертация (`conversion`).*

Машинная запись второго звена провенанса: каким конвертером и какой его версией
канонический текст произведён из сырья. Через неё транскрипции (OCR, диаграммы)
наследуют свою оговорку.

### Якорь провенанса (ProvenanceAnchor)
*Порода: данные (`data`) — хранимое с собственной схемой; получит pydantic-модель и дифф с ней. Слой: Конвертация (`conversion`).*

Тройка **(версия содержимого, хэш канонического текста, символьный интервал)** —
публикуемый стабильный адрес улики. Не зависит от нарезки на фрагменты и её версий.
Якоря живут **только в оригинале**: перевод не бывает носителем якорей.

### Фрагмент (Fragment)
*Порода: производное (`derived`) — восстановимо из источника, назад не пишет; инвалидируется версией. Слой: Обогащение (`enrichment`).*

Производная единица поиска — отрезок канонического текста с известным интервалом.
Пересоздаётся свободно при смене нарезки; долгоживущие ссылки на фрагменты запрещены —
ссылаются на якоря.

### Перевод (Translation)
*Порода: производное (`derived`) — восстановимо из источника, назад не пишет; инвалидируется версией. Слой: Обогащение (`enrichment`).*

Производное представление версии содержимого для чтения и, при необходимости,
эмбеддинга. Линза, не носитель якорей; извлечение утверждений идёт по оригиналу.

## Факты и граф

### Утверждение (Claim)
*Порода: данные (`data`) — хранимое с собственной схемой; получит pydantic-модель и дифф с ней. Слой: Обогащение (`enrichment`).*

Значение, не сущность: «Документ W в версии V утверждает X». Идентичность производна
от (якорь, нормализованное содержание). Якорь обязателен — проверяется на входе,
утверждение без якоря непредставимо. Опциональная реляционная структура
(субъект-сущность, предикат из малого словаря, объект) делает утверждение ребром
графа. Метка происхождения: deterministic / inferred / human-curated. Утверждение —
позиция документа, не истина о мире.

### Типизированная ссылка (TypedReference)
*Порода: данные (`data`) — хранимое с собственной схемой; получит pydantic-модель и дифф с ней. Слой: Обогащение (`enrichment`).*

Ребро документ↔документ (cites / amends / implements / supersedes; словарь на основе
онтологии ELI). Добывается детерминированно: из payload коннектора либо
сопоставлением идентификаторов в тексте с координатами известных корпусу работ;
текстовая находка несёт якорь. Висячие ссылки (цитируется, но в корпусе нет) —
машинные подсказки добычи.

### Сущность мира (WorldEntity)
*Порода: данные (`data`) — хранимое с собственной схемой; получит pydantic-модель и дифф с ней. Слой: Обогащение (`enrichment`).*

Узел графа: организация, страна, технология и т.п. Нормализация поверхностных форм —
через человеко-писаную таблицу (см. открытые пункты: разрешение сущностей).

### Контролируемый словарь (ControlledVocabulary)
*Порода: файл данных (человек) (`data_file`) — человеко-писаный файл значений; кода не имеет, валидируется в CI. Слой: Сквозное основание (`foundation`).*

Внешний словарь значений классификации; проверяется в CI; код по значениям не
ветвится. Писатель — человек (кардинальность десятков).

### Таблица авторитетности (AuthorityRuleTable)
*Порода: файл данных (человек) (`data_file`) — человеко-писаный файл значений; кода не имеет, валидируется в CI. Слой: Сквозное основание (`foundation`).*

Человеко-писаная таблица: (издатель, тип, обязательность, уровень) → класс
авторитетности. Документы получают класс вычислением, никогда — рукой.

### Граф (GraphLayer)
*Порода: производное (`derived`) — восстановимо из источника, назад не пишет; инвалидируется версией. Слой: Обогащение (`enrichment`).*

Производный слой: узлы — работы, сущности мира, темы; рёбра — типизированные ссылки
и утверждения; поверх — производные агрегаты. Мультиструктурность — проекции по
типам рёбер, каждая со своей кластеризацией сообществ; иерархии самособираются из
данных, несут метку inferred и служат навигации, не фактам. Человек пишет только
мета-уровень: словари типов узлов и предикатов, посев таблицы нормализации.

### Словесная обвязка (VerbalizedGraphContext)
*Порода: производное (`derived`) — восстановимо из источника, назад не пишет; инвалидируется версией. Слой: Обогащение (`enrichment`).*

Текстовый контекст (сущности, связи, принадлежность), приписываемый фрагменту перед
эмбеддингом — так граф входит в вектора через текст. Вход эмбеддера ≠ заякоренный
текст: что подавалось модели — параметр в манифесте деривации, якорей не касается.

## Реестр и хранение

### Реестр корпуса (CorpusRegistry)
*Порода: хранилище (`store`) — носитель хранения; цель связей размещения. Слой: Реестр корпуса (`registry`).*

Картотека корпуса, версионируется в git рабочего пространства. На документ — два
файла с разными писателями: машинная запись (record; человек не правит никогда)
и необязательные разреженные поправки (overrides; единственная руками правимая
поверхность; поправка бьёт машинное значение). Граница хранения по смыслу:
**членство в корпусе и жизненный цикл → git; ход обработки → машинное хранилище.**
Кандидаты до приёмки записей в git не имеют. Коммит реестра — то, чем штампуются
деливераблы.

### Машинное хранилище (MachineStore)
*Порода: хранилище (`store`) — носитель хранения; цель связей размещения. Слой: Сквозное основание (`foundation`).*

Встраиваемое бессерверное табличное хранилище машинного состояния: журналы,
утверждения, якоря, очереди склеек, курсоры, уверенности. Это роль, не движок:
конкретный движок выбирается на этапе реализации измерением.

### Векторный индекс (VectorIndex)
*Порода: производное (`derived`) — восстановимо из источника, назад не пишет; инвалидируется версией. Слой: Обогащение (`enrichment`).*

Производный слой: плотные вектора фрагментов от одной мультиязычной облачной
модели (роль; конкретная модель и точность — выбор этапа реализации). Несёт
манифест деривации; вход эмбеддера ≠ заякоренный текст.

### Лексический индекс (LexicalIndex)
*Порода: производное (`derived`) — восстановимо из источника, назад не пишет; инвалидируется версией. Слой: Обогащение (`enrichment`).*

Производный слой: локальный полнотекстовый канал класса BM25 — точность по
идентификаторам и числам. Движок — выбор этапа реализации; несёт манифест
деривации.

### Манифест деривации (DerivationManifest)
*Порода: данные (`data`) — хранимое с собственной схемой; получит pydantic-модель и дифф с ней. Слой: Сквозное основание (`foundation`).*

Паспорт производного артефакта: коммит реестра + версии записей деривации
(экстракторов, модели эмбеддинга, параметров входа).

### Корпус (Corpus)
*Порода: термин (`term`) — статья словаря без собственного носителя: ни кода, ни атрибутов. Слой: Реестр корпуса (`registry`).*

Не хранимая сущность, а предикат состояния: корпус = все активные документы реестра.
Нет id, нет конфигурации, нет собственного жизненного цикла.

### Рабочее пространство (Workspace)
*Порода: хранилище (`store`) — носитель хранения; цель связей размещения. Слой: Сквозное основание (`foundation`).*

Директория корпуса, индексов и деливераблов со своим git — всегда отдельно от
репозитория кода.

## Процессы

### Минимум приёмки (AdmissionMinimum)
*Порода: процесс (`process`) — поведение; своего хранения не имеет. Слой: Реестр корпуса (`registry`).*

Именованная, версионируемая, машинно-проверяемая политика: без чего кандидат не
становится активным. Одна функция структурных инвариантов: загрузчик падает,
валидатор собирает. Состав — открытый пункт с обязательным доуточнением.

### Триаж (Triage)
*Порода: процесс (`process`) — поведение; своего хранения не имеет. Слой: Триаж и дедупликация (`curation`).*

Суждение о включении кандидата в корпус — на полных данных, после скачивания и
конвертации. Сначала правила, дешёвая модель — где правил мало. Вердикт с причиной
записывается; процедуры удаления не существует: сырьё остаётся, история остаётся,
пере-триаж — реконсиляция при смене политики.

### Дедупликация (Deduplication)
*Порода: процесс (`process`) — поведение; своего хранения не имеет. Слой: Триаж и дедупликация (`curation`).*

Две точки принуждения. На входе — только детерминированное, автоматически: хэш
payload (зеркала) + белый список надёжных координатных схем (URL не склеивает
никогда). После приёмки — нечёткое, только предложениями: близость векторов +
нормализация названий → очередь куратору. Ложная склейка хуже пропущенной.

### Склейка (MergeOperation)
*Порода: процесс (`process`) — поведение; своего хранения не имеет. Слой: Триаж и дедупликация (`curation`).*

Операция над живыми документами: выживший Document забирает линейки версий;
идентификатор дубля становится вечным алиасом — не удаляется и не переиспользуется.

### Обогащение (Enrichment)
*Порода: процесс (`process`) — поведение; своего хранения не имеет. Слой: Обогащение (`enrichment`).*

Производство хранимых производных слоёв в стиле реконсиляции. Всё производное
восстановимо из корпуса и никогда не пишет назад. Двухуровневая инкрементальность:
единица пере-деривации — версия содержимого; единица дорогого перерасчёта —
контент-адресованный фрагмент.

### Очередь исключений (ExceptionQueue)
*Порода: процесс (`process`) — поведение; своего хранения не имеет. Слой: Триаж и дедупликация (`curation`).*

Единственная точка, где машина зовёт человека внутрь потока данных: неуверенные
извлечения и неоднозначные склейки. Состав и правила — открытый пункт
(спецификация обогащения).

### Реконсиляция (Reconciliation)
*Порода: процесс (`process`) — поведение; своего хранения не имеет. Слой: Сквозное основание (`foundation`).*

Дисциплина батчей: работа выводится из состояния мира, не из хранимого флага;
повторный прогон — пустая операция; чинится история, а не только будущее. Отказ
элемента не роняет батч; аварийность выше порога прерывает прогон; чекпоинты,
идемпотентные единицы.

## Запросы и синтез

### Слой запросов (QueryLayer)
*Порода: процесс (`process`) — поведение; своего хранения не имеет. Слой: Слой запросов (`query`).*

По-вопросные вычисления, ничего не хранит. Гибридный поиск (плотные вектора из
облака + локальный лексический канал) → слияние → посевные узлы → расширение по
графу (Personalized PageRank) → выдача с якорями. Будущий реранкер — ступень здесь.
Проверка свежести — по манифестам деривации, с честным объявлением отставания. Путь ответа обязан
отказаться («в корпусе этого нет»), а не догадаться. Тренды — счётные запросы к
слою утверждений; семантика числа: представленность в корпусе, не независимая
корроборация.

### Запрос тренда (TrendQuery)
*Порода: процесс (`process`) — поведение; своего хранения не имеет. Слой: Слой запросов (`query`).*

Счётный запрос к слою утверждений: считаются работы, не языковые копии.
Семантика числа — представленность в корпусе, не независимая корроборация;
свёртка цитирований — этап 2.

### Деливерабл (Deliverable)
*Порода: данные (`data`) — хранимое с собственной схемой; получит pydantic-модель и дифф с ней. Слой: Мастерская синтеза (`synthesis`).*

Итоговый документ: Markdown в git рабочего пространства, версионируем по построению.
Каждая версия штампуется манифестом деривации. Семейство вариантов — над явно
записанной матрицей параметров.

### Валидатор деливерабла (DeliverableValidator)
*Порода: процесс (`process`) — поведение; своего хранения не имеет. Слой: Мастерская синтеза (`synthesis`).*

Механический контролёр черновика: каждое фактическое утверждение несёт разрешимую
ссылку на якорь; не имеющее ссылки либо явно помечено как суждение автора, либо
удаляется.

## Сквозное

### Сетевой клиент (NetworkClient)
*Порода: процесс (`process`) — поведение; своего хранения не имеет. Слой: Сквозное основание (`foundation`).*

Единственный модуль всех исходящих вызовов — и моделей, и скачивания: повторы с
нарастающими паузами и разбросом, распознавание ошибки внутри успешного ответа,
немедленный отказ на постоянных ошибках, вежливость к сайтам, бюджетные
предохранители на прогон.

### Замок писателя (WriterLock)
*Порода: процесс (`process`) — поведение; своего хранения не имеет. Слой: Сквозное основание (`foundation`).*

Один замок на все пишущие операции рабочего пространства, включая каждую подкоманду;
чтение — без замка, по снимку.
