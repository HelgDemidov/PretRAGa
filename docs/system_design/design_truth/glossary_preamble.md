## Терминологические конвенции

- Слово **«источник»** в модели данных не используется. В живой речи оно означает
  отдельную публикацию/документ — и потому зарезервировано за человеческим языком.
  Поток документов из настроенного места добычи называется **каналом добычи**.
- **«Кандидат»** — не сущность, а стадия жизненного цикла Документа (до приёмки в корпус).
- Код — только английский; в скобках у каждой сущности — её имя в коде.

## Конвенции идентичности

- Сущность с жизненным циклом получает **чеканный идентификатор** (непрозрачный,
  время-упорядоченный, класса UUIDv7) один раз, при первом появлении; он никогда не
  пересчитывается и не участвует в сравнении «то же самое или нет».
- Неизменяемое значение **контент-адресуется** — ключ равен хэшу содержимого.
- Сравнение и сопоставление — отдельный механизм на отдельных атрибутах
  (естественных координатах); ненадёжное значение не даёт ключа вовсе.
- Ключ, разрешающийся в несколько сущностей, отзывается; сущности не сливаются автоматически.

## Конвенции писательства

- У каждого артефакта **один писатель**; писатель по умолчанию — машина.
- Поле, которое может заполнить только человек, обязано оправдать себя на
  кардинальности десятков (каналы, словари, таблицы правил), а не тысяч (документы).
  У документа обязательных ручных полей — ноль.
- Человеческие решения входят в систему **командами инструмента**, а не правкой
  машинных файлов; единственная руками правимая поверхность — файлы поправок.
- Машина никогда не пишет в человеческие файлы.
